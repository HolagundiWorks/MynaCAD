# Releasing MynaCAD

The canonical recipe is craftrules' [`release/playbook.md`](https://github.com/storytold/craftrules/blob/main/release/playbook.md); this file covers only what's AAD-specific.

**Supported platform for now: Windows only.** The macOS, Linux and web release steps below are kept for the later phases and are not part of the current product.

- **Version:** `[workspace.package] version` in the root `Cargo.toml` is the single source. `cargo xtask version` prints it; `cargo xtask version set X.Y.Z[-pre]` changes it. The app shows it in About, `aad --version` and `aad-cli --version`; release builds also embed the commit (`AAD_BUILD_SHA`).
- **Cut a release:** bump the version on `main`, then push `main` to `release` (`git push origin main:release`). Every push to `release` runs `.github/workflows/release.yml` and creates or updates the draft GitHub Release `AAD v<version>`. A `workflow_dispatch` run with `version: X.Y.Z-rc.N` makes a test build. A dispatch on any other branch is a dry run: the unsigned jobs (version, Linux, Linux riscv64, Flatpak, FreeBSD, web) build, the `release` environment refuses the signing jobs (macOS, Windows), and no release is drafted.
- **Artifacts:** macOS universal `.dmg` (Developer ID signed, notarized, stapled) and CLI `.zip`; Windows x64, x86 and arm64 `.msi` + portable `.zip` (Azure Trusted Signing); Linux x86_64 and aarch64 `.AppImage` (+ `.AppImage.zsync` for AppImageUpdate delta updates), `.flatpak` bundle (repackages the tarball, `packaging/linux/flatpak-bundle.sh`), `.deb`, `.rpm`, `.tar.gz` (+ the from-source Flathub manifest in `packaging/linux/flatpak/`); Linux riscv64 `.tar.gz` (cross-compiled on Ubuntu 24.04 against ports.ubuntu.com riscv64 libraries, CLI smoke-tested under QEMU); FreeBSD x86_64 `.tar.gz` (built in a FreeBSD VM); web `.zip` (wasm + `index.html`, see `packaging/web/README.md`); `SHA256SUMS.txt`.
- **Secrets:** the twelve signing secrets live in the `release` environment (deployable only from the `release` branch, which only org admins and release-managers can push). All are optional: a missing one produces unsigned artifacts with a warning. **Once Windows Azure or PFX secrets are pasted, the next `release` workflow run signs automatically** — no further code change. Shared Windows names (suite-wide): `WINDOWS_CERTIFICATE` (+ password), or `AZURE_TENANT_ID` / `AZURE_CLIENT_ID` / `AZURE_CLIENT_SECRET` / `AZURE_SIGNING_ACCOUNT` / `AZURE_CERT_PROFILE` plus `AZURE_SIGNING_ENDPOINT` or `AZURE_SIGNING_REGION`. Windows Azure signing may use OSSign (`packaging/windows/sign.ps1`, example `ossign.config.example.yaml`) when `ossign.exe` is available. Local Windows packaging can use `SIGN_SELF_SIGNED=1` for a development Authenticode cert under `%LOCALAPPDATA%\O-Draft\dev-codesign\` (SmartScreen still warns). Never commit private keys, PFX files, or filled OSSign configs ([threat-model.md](threat-model.md), [RELEASE_AND_PACKAGING.md](RELEASE_AND_PACKAGING.md)). Suite ops enrollment (Azure Trusted Signing vs EV purchase): Project doc `suite-installer-signing.md`.
- **SBOM:** `cargo xtask sbom` writes a CycloneDX 1.5 JSON BOM from locked `cargo metadata` (no secrets). The release workflow uploads `o-draft-<version>.cdx.json` beside the other artifacts.
- **Windows installer:** `packaging/windows/aad.wxs` (WiX v5 + `WixToolset.UI.wixext`). Wizard: Welcome (splash bitmap) → open-source EULA (`EULA.rtf`, MIT OR Apache-2.0) → Shortcuts → Ready. The Start Menu shortcut is always created; the desktop shortcut is opt-in (`DESKTOPSHORTCUT=1` for silent installs, `DESKTOPSHORTCUT=0` drops it on an upgrade; otherwise upgrades keep the previous choice). AI edition: `packaging/windows/package.ps1 -Arch x64 -Assistant` → `o-draft-ai-<version>-windows-x64.msi` (bundles the local model).
- **File types:** `.dxf` and `.dwg` (macOS document types, Windows "Open with", Linux MIME types).
- **Local packaging test:** `packaging/macos/package.sh` (ad-hoc signed DMG), `packaging/linux/package.sh`, `packaging/web/package.sh`.
- **Icons and logo:** the MynaCAD bird is drawn in code (`xtask/src/logo.rs`, the same curves as `o-ui` `tools/Brand`; vector copy in `assets/app-icon/aad-logo.svg`). `cargo xtask logo` regenerates every icon (PNG sizes, Linux hicolor, `.ico`, `.icns`); the outputs are committed, so builds need no image tools.
