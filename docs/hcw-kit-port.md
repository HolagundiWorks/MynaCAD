# hcwCAD-KIT port

hcwCAD-KIT (MIT, Holgundi Consulting Works) is a legacy C# architectural toolkit. Its tools are rebuilt
here in Rust as built-in commands (`crates/engine/src/cmd/`), not as an add-on. Each tool is a
normal command: JSON form, menu entry under **Architecture**, tests. Behaviour reference: the
kit's README (`/HolagundiWorks/hcwCAD-KIT`). No C# source is included.

## Done

| Area | Tren commands | Notes |
|---|---|---|
| Layer sets | `hcwlayers` `{set: standard\|permit\|presentation\|both\|all}` | Creates missing layers only; unknown linetypes fall back to Continuous. Aliases: `hcw`→`standard`, `bp`→`permit`. **standard**: 36 AIA-style layers (`A-WALL`, `AN-TEXT`, …). **permit**: `BP-*` building-permit layers (names kept for AutoPlan interchange). **presentation**: `G-HEAVY`…`G-ANNO` graphic-weight layers with plot styles for `presentation.stb` |
| Room tools | `room.relabel`, `room.log`, `room.total`, `room.audit`, `room.check`, `room.lighting` | From `hcwtools.lsp` section 11 (MRELABEL, MSCHEDULE, MTOTAL, MAUDIT, MCHECK). The three lines of a room label are paired by position, not by drawing order, so a log and a total are right whatever order the labels were drawn in. MFLOOR is the active floor of `floors`, which `room` already uses. `room.lighting` reads each declared room and reports maintained illuminance in lm/m² and lm/ft², plus that level times the room area. The table is ours (circulation, toilets, offices and stores follow published maintained levels for those uses; other rooms use one general level). It is not a certified copy of EN 12464-1, the IES Lighting Handbook, or IS 3646. The same fields are written on the room row of `bridge.export` / `takeoff.record` |
| Legacy toolkit | `vhlayers`, `layermap`, `deleteareatext`, `polyarea` | `vhlayers`: the 75-layer VH set. `layermap` takes a map of old to new layer names (no dialog), moves objects in every space, and can purge the emptied layers; objects on locked layers stay. `polyarea` closes open polylines first unless `close` is false |
| Building permission (BPLT) | `bpltstart`, `bpltlayers`, `bpltcopy`, `bpltcheck`, `bpltarea`, `bpltreport`, `bplttitleblock` | From `hcwtools.lsp` section 6 and 9, for the BBMP BPAS / AutoPlan workflow: metres at 1:1, 65 BP- drafting layers and 27 non-plotting AP- marking layers. `bpltstart` scales the model to metres from `INSUNITS` once (skipping locked layers) and sets `BPLT-DIM`. `bpltcheck` and `bpltarea` read closed lightweight polylines only |
| Standard layer tools | `hcwreset`, `hcwinfo`, `hcwlock`, `hcwunlock`, `hcwaudit2`, `hcwbyblock`, `hcwmove`, `hcwschedule`, `hcwlegend` | Menus under **Architecture ▸ Standard Layers**. Command ids keep the `hcw*` prefix. The standard has 36 layers (the toolkit said 35). HCWPURGE and HCWAUDIT are the existing `purge` and `audit`; HCWLAYERSTATE is `layerstate.*`. The legend is sized as for metres at 1:1 and scaled to the drawing units |
| Text tools | `fixtxt`, `fixtxth`, `txtalign`, `txtdup`, `txtaudit`, `txtexport`, `txtinc` | From the AutoLISP toolkit `hcwtools.lsp` (same authors). `txtalign` sets the insertion point on one axis; `txtinc` is JSON-only (no prompt sequence yet) |
| Rooms | `room` (aliases `hcwroom`, `roomc`), `rarea` | 29 room codes; label with name, size and area; units from the drawing units |
| Project data | `project`, `floors`, `beams`, `levels` | Stored in the drawing (`Drawing.project`, DXF XRECORD `AAD_PROJECT`). `project` is Project Settings (details plus `structure.slabMm` / `structure.beamMm`). The Floors dialog edits names only; FTF/ceiling/lintel stay as defaults for take-off. `floors` still rejects a ceiling height above the floor-to-floor height when those fields are supplied |
| Take-off | `takeoff.start` and `takeoff.linear\|brick\|beams\|columns\|rects\|paint\|ceiling\|floor\|area\|slab`, `takeoff.list`, `takeoff.clear`, `takeoff.export` | Reads the `MEASURE-*` layers. Walls are numbered left to right, then bottom to top; equal lengths or areas share a group (FB-A, FB-B ...). Metric results round to 1 cm, imperial to 1/8 in. Tables are drawn in the drawing and results are saved with it. CSV export only |
| Deductions | `MEASURE-DEDUCT` lines, including lines inside blocks | Door and window blocks made by `wall.door` and `wall.window` carry their own deduction line |
| Rates and bill | `takeoff.rates`, `takeoff.bill` | Rate book per item, bill of quantities from the saved take-off results |
| Schedules | `schedule`, `openings.std`, `openings.sync`, `openings.table` | Standard door and window set; sync counts blocks and refreshes schedule width (`length`) from opening inserts on the drawing; table drawn on request |
| Walls and openings | `wall.draw`, `wall.door`, `wall.window`, `wall.clean` | Faces mitred at corners, end caps on open ends, openings cut both faces; door/window can grab a plan `block` and take opening width from it (or an override) into the schedule; `wall.draw` is command-line / script (not on the Architecture bar); `wall.clean` erases zero-length and duplicate lines and joins overlaps |
| Structure | `grid.axis`, `column.place`, `column.schedule`, `lintel.draw`, `stair.plan`, `lift.shaft`, `rail.draw` | The grid is remembered; columns go on its intersections; lintels get a 150 mm bearing each side; stairs report risers, goings and concrete volume |
| Levels and symbols | `level.mark`, `level.schedule`, `section.marker`, `elevation.marker`, `north.arrow`, `slope.arrow` | Level marks are stored so `level.schedule` lists them in ascending order |
| Electrical layout | `electrical.blocks`, `electrical.number`, `electrical.layers`, `electrical.connect`, `electrical.schedule`, `electrical.update`, and the place tools `elec.light`, `elec.socket`, `elec.switchboard`, `elec.fan.ceiling`, `elec.downlight`, `elec.db` | 17 symbol codes (SB, LP, FP, EF, SW1, SW2, CB, P5, P15, AC, WP, GY, FR, OV, WF, TV, INV). A point that reaches two boards is reported, not counted. The place tools insert the parametric symbols; they do not size a circuit. On the left tool column while the Electrical tab is active |
| Plumbing layout | `plumbing.blocks`, `plumbing.number`, `plumbing.layers`, `plumbing.pipe` (and `plumbing.pipe.cold`, `.hot`, `.drain`), `plumbing.fittings`, `plumbing.autofit`, `plumbing.connect`, `plumbing.schedule`, `plumbing.update`, and the place tools `plumb.wc.european`, `plumb.wc.indian`, `plumb.basin`, `plumb.sink.kitchen`, `plumb.shower`, `plumb.floor.trap`, `plumb.chamber`, `plumb.tank.round`, `plumb.riser` | 10 codes (fixtures WC, IWC, WB, KS, SH, FT; sources IC, TK, RS, and WH, a water heater with no toolbar symbol that is matched by block name). Pipes are cold water (`P-WATR`, blue, 15 to 50 mm), hot water (`P-HOTW`, red, 15 to 25 mm) and drainage (`P-DRAN`, green, 50 to 150 mm); the layers are the standard sheet-set ones (`P-HOTW` is new). Each run is a solid polyline as wide as its pipe, whatever the layer's linetype. The three are separate networks because a fixture normally has more than one; hot water is optional, so a fixture without it is not flagged. Fittings (elbows, tees, reducers) are added at bends and junctions as pipes are drawn. A fixture reaching two sources of one service is reported, not counted. Schedules: fixtures per source, one row per fixture, pipe length by service and diameter. On the left tool column while the Plumbing tab is active |
| Plumbing symbols | `plumb.wc.european`, `plumb.wc.indian`, `plumb.basin`, `plumb.sink.kitchen`, `plumb.shower`, `plumb.floor.trap`, `plumb.chamber`, `plumb.tank.round`, `plumb.riser` | The same symbols as the Blocks panel, also under Architecture > Plumbing and on the left tool column while the Plumbing tab is active. No pipe router |
| Interior symbols | `int.bed`, `int.sofa`, `int.dining.set`, `int.kitchen.counter`, `int.wardrobe`, `int.shelf` | The same symbols as the Blocks panel, also under Architecture > Interior and on the left tool column while the Interior tab is active |
| False ceiling symbols | `hvac.diffuser.square`, `hvac.grille`, `hvac.duct.rect`, `hvac.fan.exhaust`, `hvac.split.indoor`, `hvac.split.outdoor`, `elec.downlight`, `elec.fan.ceiling` | The same symbols as the Blocks panel, also under Architecture > False ceiling and on the left tool column while the False ceiling tab is active. No duct router |
| AQC bridge | `bridge.export`, `bridge.import` | File format `hcw-aqc-bridge` version 1, millimetres. Export writes project details, floors, beam depths, the opening schedule, door and window blocks, and walls, columns, lintels and slabs from the saved take-offs, beside the drawing as `name.aqc.json`. Import reads AQC's project details, floors and beam depths; it previews first, applies only on `apply` (the Apply button in the menu flow), leaves filled fields alone unless `overwrite`, asks for confirmation when the file came from another drawing, and never changes geometry. Not exported: wall thickness. Rooms (name, size text, area in m2) and the drawing revision (`source.revision`: SHA-256, bytes, save time, entity count, given only while the saved file still matches it) are additive keys; format version stays 1 |

Limits that are stated, not hidden: electrical layout does not size circuits, compute loads or
measure cable length; plumbing layout does not size pipes, count fixture units, set slopes or invert
levels, or place fittings and valves, and a riser's service (soil, waste, rainwater, vent, cold, hot) is
a block parameter the block name does not carry, so every riser is a source for both services; `stair.plan` draws a plan only; no section is drawn from the plan.
